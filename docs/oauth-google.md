# OAuth через Google: как это работает

Файлы: `internal/core/transport/http/oauth/google.go` (хендлеры) и `store.go` (хранилище пользователей).

Главный принцип: **Google нужен только чтобы один раз узнать «кто это»**.
Дальше по сервису ходит НАШ собственный EdDSA-JWT с claim `user_id` —
его проверяет `middleware.AuthMiddleware`. Google-токен после входа выбрасывается.

## Карта потока (Authorization Code flow)

Участники: Браузер (юзер), Наш сервер, Google.

```
 БРАУЗЕР (юзер)                НАШ СЕРВЕР                       GOOGLE
      |                             |                             |
      |  1. GET /auth/google/login  |                             |
      |---------------------------->|                             |
      |                             |  генерим state (случайная   |
      |                             |  строка, защита от CSRF)    |
      |                             |  кладём state в cookie      |
      |    2. redirect на Google    |   oauth_state               |
      |<----------------------------|                             |
      |                             |                             |
      |  3. GET accounts.google.com/o/oauth2/auth?                |
      |        client_id=...&state=...&redirect_uri=...           |
      |---------------------------------------------------------->|
      |                             |                             |
      |     4. экран «разрешить?» — юзер жмёт «Продолжить»        |
      |<----------------------------------------------------------|
      |                             |                             |
      |  5. redirect: /auth/google/callback?code=XXX&state=YYY     |
      |<----------------------------------------------------------|
      |                             |                             |
      |  6. GET /auth/google/callback                             |
      |     ?code=XXX&state=YYY     |                             |
      |---------------------------->|                             |
      |                             |  7. state из query == state |
      |                             |     из cookie?  (анти-CSRF) |
      |                             |                             |
      |                             |  8. POST token endpoint     |
      |                             |     code=XXX                |
      |                             |     + client_secret         |
      |                             |     (сервер-сервер,         |
      |                             |      браузер не видит)      |
      |                             |---------------------------->|
      |                             |      access_token           |
      |                             |<----------------------------|
      |                             |                             |
      |                             |  9. GET /v1/userinfo        |
      |                             |     (Bearer access_token)   |
      |                             |---------------------------->|
      |                             |     {sub, email, name}      |
      |                             |<----------------------------|
      |                             |                             |
      |                             |  10. store.FindOrCreate(    |
      |                             |       "google", sub, ...)   |
      |                             |      -> наш user_id         |
      |                             |                             |
      |                             |  11. подписываем СВОЙ JWT   |
      |                             |      (EdDSA, exp 24ч)       |
      |                             |                             |
      |  12. 200 {token, user_id,   |                             |
      |          email, name}       |                             |
      |<----------------------------|                             |
      |                             |                             |
      |  13. дальше все запросы по  |                             |
      |      сервису: Authorization: Bearer <наш JWT>             |
      |---------------------------------------------------------->|
      |                    (Google больше не участвует)           |
```

## Что есть что

| Сущность | Кто выдаёт | Зачем | Жизнь |
|---|---|---|---|
| `state` | наш сервер, на шаге 1 | защита от CSRF (см. ниже) | 5 мин, в cookie |
| `code` | **Google**, на шаге 5 | одноразовый «билет» на обмен | минуты, одноразовый |
| access_token Google | Google, на шаге 8 | дёрть userinfo один раз | час; мы не храним |
| наш JWT | наш сервер, шаг 11 | ходить по нашему API | 24 ч |

## Зачем код и зачем state (две разные защиты)

**state — защита от подмены «начала» потока (CSRF).**
Злоумышленник может подсунуть жертве СВОЙ code и заставить её браузер открыть
наш callback — жертва залогинится под аккаунтом атакующего. Против этого:
state генерим мы, кладём в cookie браузера и передаём через Google; в callback
сверяем «state из query == state из cookie». Атакующий не знает случайный state
чужого браузера — подделать начало не может.

**code — защита от утечки токена через браузер.**
Токен по браузеру вообще не ходит: Google отдаёт браузеру только одноразовый
code, а токен выдаёт лишь в ответ на code + client_secret (секрет знает только
наш сервер, шаг 8 идёт сервер-сервер). Укравший code (по логам, рефререру,
истории) без client_secret ничего с ним не сделает; сам code одноразовый и
быстро протухает.

## Ручки

- `GET /auth/google/login` — редирект на Google, до этого кладёт state в cookie.
- `GET /auth/google/callback` — сюда Google возвращает юзера. Внутри по шагам:
  сверить state -> обменять code на токен -> взять профиль -> FindOrCreate ->
  выдать наш JWT.

## Ключ связи пользователей

Google в профиле отдаёт `sub` — постоянный ID юзера внутри Google.
Именно `sub`, а не email, служит ключом: email человек может сменить, sub — нет.
`store.FindOrCreate("google", sub, email, name)` возвращает наш внутренний
`user_id`, заводя запись при первом входе.

## store.go

`UserStore` — интерфейс с методом `FindOrCreate(provider, providerUserID,
email, name) int64`. Хендлеры зависят только от интерфейса.

`MemoryStore` — единственная реализация, in-memory: map
`"provider|sub" -> user_id`, при первом входе инкрементит счётчик. Оговорки:
- всё пропадает при рестарте процесса;
- email/name принимаются, но пока не сохраняются.

Позже за тем же интерфейсом встаёт Mongo/SQL — хендлеры не меняются.

## Настройка

clientID/clientSecret — из Google Cloud Console; redirectURL должен совпадать
с прописанным там же (например `http://localhost:8080/auth/google/callback`).
Scopes: `openid email profile`. Приватный ключ Ed25519 — тот же, что для
остальных наших JWT.
