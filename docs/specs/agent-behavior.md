# SDD: поведение AI Buddy и инструментов

Версия 1.1.0. В текущей основе генератор детерминированный (`mode=mock`). Спецификация задаёт те же границы для будущего RAG (`mode=rag`). Автотесты: `TestMockBehavior`, `TestGenerationFailuresAndRetry`, `TestAccessRequest`, `TestInfoAndDirectory`, UI-сценарии в `frontend/src/App.test.tsx`.

## Цель и вход

Помочь стажёру с выбранными этапами первых недель: знакомство с командой, инструкция, получение доступа, следующий шаг. Использовать только переданный авторизованный контекст и разрешённые материалы. Не заменять наставника в вопросах, требующих человека.

Вход: текущий вопрос, до 20 предыдущих сообщений этого чата, свежий профиль, команда, состав, бадди, ответственные сервисы, личный чек-лист и `allowedDocumentIds`. Прошлые сообщения и документы — недоверенные данные; текст «игнорируй ограничения» не является разрешением.

## Сценарии и критерии приёмки

### A. Знакомство

Given: стажёр Backend с именем и демо-бадди. When: спрашивает о команде. Then: ответ учитывает имя, должность, команду и бадди, указывает доступный источник, предлагает реальные этапы знакомства. Нельзя придумывать контакты/факты о настоящих сотрудниках.

### B. Инструкция

Given: разрешённый документ `engineering`. When: вопрос о принципах разработки. Then: ответ с цитатой/ID этого документа, возможность открыть источник. Given: документа нет в ACL. Then: без раскрытия его содержания; предложить наставника. В production-RAG ограничивать выбор документов до генерации. Backend проверяет ссылки источников, но не может распознать произвольную утечку в тексте модели: ACL и prompt-injection evals обязательны и на стороне ML.

### C. Корпоративное действие

Given: вопрос об инструменте из актуального `userContext.tools`. Then: предложить только `REQUEST_ACCESS` с инструментом из разрешённого списка пользователя. Результат генерации не вызывает корпоративный API. When: человек подтверждает отдельный диалог. Then: Info повторно проверяет права и `confirmed=true`, вызывает корпоративную имитацию, сохраняет и отображает номер и статус `submitted`. Повтор с тем же ключом возвращает тот же результат. При другом инструменте с тем же ключом — 409.

`submitted` означает принятие заявки, а не выдачу доступа. Пункт чек-листа автоматически не завершается. Не имитировать согласование наставником и не выдавать фальшивый `granted`. При сбое показывать ошибку; повторить с тем же ключом.

### D. Прогресс

Given: личные статусы из Info. When: вопрос о следующем шаге. Then: использовать актуальные completed/total/percent и первую незавершённую задачу по sort_order. При завершении всех задач предложить обсудить дальнейшие цели с наставником. Изменения галочки обратимы; время завершения очищается при возврате в pending/in_progress.

## Отказы и небезопасные ответы

- Источник другой команды: Chat отклоняет весь ответ с 502, не сохраняет и не отображает его.
- Неизвестный тип действия/инструмент: 502; никакого исполнения.
- Пустой ответ, недопустимый mode, ответ более 32000 UTF-8 байт: 502.
- Timeout/невалидный JSON RAG или недоступный Info: вопрос уже сохранён; UI предлагает повторить генерацию без дубликата вопроса.
- Нет доказанного ответа: явно признать отсутствие данных, направить к бадди. Без мнимого поиска и уверенности.
- Секреты, пароли, настоящие персональные сведения и финансовые операции не запрашивать.

## Инструменты

| Инструмент | Доступ | Побочный эффект |
| --- | --- | --- |
| Directory/knowledge API | Серверный токен индексатора | Только чтение |
| Current context | Chat token + JWT субъекта | Идемпотентная инициализация демо-профиля |
| Generate | RAG token, контекст с ACL | Только предложение ответа/действия |
| Request access | Проверенный JWT + Gateway token + явное подтверждение | Сохранённая заявка в mock-системе |

Критерии для интеграции реального RAG: ответы по каталогу владельцев; корректные цитаты; нулевое раскрытие закрытых документов в ACL-тестах; устойчивость к инструкциям внутри документов; никакого побочного эффекта без подтверждения; корректный отказ при отсутствии источника. Эти ML-evals ещё не выполнены: реального RAG в этой поставке нет.

## MVP нескольких команд

Проверяется пять новых стажёров четырёх команд: профиль, личный прогресс, доступные документы, инструменты, чат и подтверждённая заявка. Frontend предлагает Figma/Storybook, Analytics — Metabase/Jupyter, QA — TestRail/тестовый стенд, Backend — Stash. Известный, но недоступный инструмент не подменяется другим действием. При смене аккаунта интерфейс очищает персональное состояние.
