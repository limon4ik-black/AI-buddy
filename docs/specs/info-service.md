# Info Service v1: контракт с RAG

Статус: реализован HTTP read API, PostgreSQL, seed-данные и автоматические проверки. Формат — REST/JSON, без gRPC. Машиночитаемый контракт: `api/openapi-info-internal.yaml`. Готовые вызовы: `api/info-examples.http`. Клиент для коллеги: `examples/rag_client.py` (стандартная библиотека Python).

## Что хранит сервис

| Сущность | Содержание | Связи |
| --- | --- | --- |
| `teams` | Название, описание, `buddy_id` | Бадди обязан состоять в команде |
| `people` | Только синтетические имя и должность | Без телефона, личного email и чувствительных данных |
| `team_members` | Человек, команда, роль: lead / buddy / engineer | Человек может состоять в нескольких командах |
| `technical_services` | Название, назначение, lifecycle, ссылки | Одна команда-владелец и ответственный из этой команды |
| `corporate_tools` | Stash, Confluence, VPN | Каталог инструментов, отдельно от технических сервисов |
| `knowledge_documents` | Инструкции, категория, источник, ACL, обновление, tombstone | Общие документы либо документы конкретной команды |
| `checklist_tasks` | Шаблоны этапов: порядок, период, описание, инструкция | Общие или командные |
| `profiles` | Пользователь Auth, команда, имя, должность, дата начала | Команда назначается организацией, не пользователем |
| `user_task_progress` | Личный статус задачи и время завершения | Отдельно от шаблона |
| `access_requests` | Результат обращения к имитации корпоративного сервиса | Пользователь, ключ идемпотентности, внешний номер |

`team_directory` — SQL view: имя бадди берётся из `people`, а не дублируется в командах. Внешние ключи проверяют состав команды и принадлежность ответственного. Идентификаторы стабильны; названия можно менять без изменения связей.

## Что получает ML-инженер

Базовый URL для Docker и локального клиента: `http://localhost:8082`. Внутри Compose: `http://info:8082`. Заголовок индексатора: `X-Service-Token: <INDEXER_SERVICE_TOKEN>`.

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/internal/v1/teams` | Все команды общего справочника |
| GET | `/internal/v1/teams/{id}` | Команда, `buddyId`, `members[]`, `services[]` |
| GET | `/internal/v1/services` | Сервисы; фильтр `?ownerTeamId=backend` |
| GET | `/internal/v1/services/{id}` | `ownerTeamId`, `technicalOwnerId`, назначение и ссылки |
| GET | `/internal/v1/checklist/templates?teamId=backend` | Общие + командные шаблоны, без личных галочек |
| GET | `/internal/v1/knowledge/documents?limit=100&after=...` | Полный снимок документов с ACL и удалениями |

Справочник команды можно превращать в текст для embeddings на стороне RAG. Например: «Команда Backend, бадди Алекс, состав Алекс/Мария/Иван, отвечает за Intern Profile API и Knowledge API». В метаданных чанка сохраняются первичный ID и тип источника. Для цитат каталога используйте `team:backend` / `service:knowledge-api`; для документов — их `id`.

В прототипе состав **всех** команд и технические владельцы — company-visible. Это сознательное правило демо-справочника. Внутренние инструкции имеют отдельное ограничение `visibility=team`. Если реальные составы команд окажутся закрытыми, до подключения настоящих данных нужно добавить их ACL в read API и индекс; нынешнее правило нельзя автоматически переносить на настоящую компанию.

## Актуальный контекст пользователя

`GET /internal/v1/context` вызывается **Chat Service** с двумя полномочиями:

```http
X-Service-Token: <CHAT_SERVICE_TOKEN>
Authorization: Bearer <accessToken стажёра>
```

Ответ: `profile`, `team` с составом и сервисами, `role`, `onboarding` с личными статусами и следующим шагом, `allowedDocumentIds` и `tools[]` — разрешённые пользователю инструменты.

Параметра `userId` нет: субъект берётся из подписанного JWT. Индексаторный токен не даёт права читать контекст. Перед каждым вопросом Chat запрашивает контекст заново и передаёт его RAG в `POST /internal/v1/generate`. Персональный прогресс нельзя помещать в векторный индекс: иначе ответ быстро устареет и появится риск раскрыть чужие данные.

## Правила индексации и доступа

1. Получить список команд, карточки, сервисы и шаблоны.
2. Прочитать документы с `after=""`. Продолжать с `after=nextCursor`, пока курсор не станет пустой строкой. Лимит — 1–100; порядок лексикографический по ID.
3. Построить новый снимок индекса отдельно. Удалить tombstones (`deletedAt != null`) и документы, отсутствующие в полном снимке. Опубликовать индекс атомарно.
4. Сохранять `documentId`, `visibility`, `teamId`, `sourceUrl`, `updatedAt` и `synthetic` на **каждом чанке**. Индексатор — доверенный сервер, он видит документы разных команд.
5. При поиске допускать только ID из `allowedDocumentIds` и `tools[]` — разрешённые пользователю инструменты. Применять фильтрацию **до retrieval / LLM**, а не только при отображении цитаты. Общие каталоги используют канонические ID `team:` / `service:`.
6. Если по вопросу нет разрешённых материалов, вернуть честное отсутствие ответа и предложить бадди. Инструкции в текстах документов — данные, они не меняют правила агента.

MVP поддерживает полный reindex; инкрементальная синхронизация, CDC и запись каталога параллельно экспорту не реализованы. Каталог небольшой, поэтому списки команд и сервисов выдаются целиком; документы имеют пагинацию. Изменения справочников сейчас вносятся контролируемой миграцией/импортом. Редактор и синхронизация с корпоративным HR-каталогом — следующий этап.

## Локальный запуск только Info

```bash
bash scripts/configure.sh
# Если установлен только Docker, генератор ключей можно запустить через Docker (см. README).
docker compose up --build -d info
set -a
source .env
set +a
mkdir -p .local
python3 examples/rag_client.py > .local/index-snapshot.json
```

Папка `.local` исключена из Git. Индексаторный токен хранится у ML-сервиса, в браузер не передаётся. В профиле автоматически создаётся демо-назначение Backend; это имитация готового корпоративного каталога, а не настоящая HR-интеграция.

## Ошибки и совместимость

`400` — формат или фильтр; `401` — токен отсутствует/неверен; `403` — операция запрещена; `404` — объект отсутствует или скрыт ACL; `409` — конфликт идемпотентности; `415` — неверный Content-Type; `502` — зависимость вернула ошибку/невалидный ответ; `503` — хранилище недоступно. JSON: `{"error":{"code":"...","message":"...","requestId":"..."}}`. Недоступный документ возвращает тот же `404`, что отсутствующий.

Версия пути — v1, версия схемы — 1.1.0. Формат полей camelCase, время UTC/RFC3339, ID — непрозрачная строка. Смена обязательного поля или типа требует новой версии/совместимого перехода. Браузерные пути находятся в `openapi-public.yaml`, внутренние не публикуются через Gateway.

## MVP-данные и инструменты

В версии 1.1.0: четыре команды (Backend, Frontend, Analytics, QA), 12 технических сервисов, 30 документов. Шаблоны включают девять общих и шесть командных задач — по 15 шагов на пользователя. Наставники, участники и пять новых стажёров синтетические.

`GET /internal/v1/context` теперь содержит `tools[]`. Каждый элемент: `id`, `name`, `description`, `teamId` (null для общего инструмента), `documentId`. Chat проверяет `suggestedAction.system` по этому списку. Индексировать личный прогресс и тестовые пароли не нужно.

Confluence/VPN доступны всем демо-командам; остальные инструменты ограничены командой. Состав каталога остаётся company-visible, а инструкции — company или team по метаданным.
